# Plan: Mesh Team CLI Adapter

## Objective

Add a KISS adapter between the existing Mesh/iTerm team controller and
`claude-config` command, validation, quality, and confidence-gate assets.

The adapter must keep the current runtime boundary intact:

- visible roles run in iTerm panes
- the controller owns execution
- role CLIs produce decisions, plans, implementation, or audit output
- tests, gates, retries, and exit status are controller-owned

## Current Runtime

Current code already supports:

- `./scripts/mesh speckit run <repo> --feature ...`
- local team presets:
  - `local-codex-gemini`
  - `local-gemini`
  - `claude-codex-gemini`
  - `env`
- `--auto`
- `--allow-edit`
- `--with-reviewer`
- handoff JSON files
- worker-only edit auto-approval
- test command execution
- non-zero exit on test failure

Primary implementation files:

- `scripts/mesh`
- `scripts/mesh_iterm_control.py`
- `tests/test_mesh_iterm_control.py`

Do not touch router/session-worker code for MVP.

## Design Decisions

### 1. Keep Mesh as executor

Claude boss may select and explain a workflow, but it does not run subordinate
CLIs or gate scripts directly.

### 2. Read, do not copy, claude-config

Mesh should resolve `claude-config` and read selected files at runtime. GobabyGo
must not fork Speckit/GSD command content unless there is a deliberate future
sync mechanism.

### 3. Use excerpts, not full documents

The adapter should inject short contract excerpts into prompts:

- title/description
- objective or process summary
- relevant constraints
- Mesh-specific forbidden actions

Avoid pasting large command files into every prompt.

### 4. Sidecars, not handoff renumbering

Existing handoff filenames stay stable. New quality/gate outputs are sidecars.

### 5. Loops are controller-owned

Ralph-style loops are valuable, but only when the controller owns iteration
state, max iterations, stop reasons, and artifacts.

## Workstreams

### W1. Adapter Source Resolution

Goal:

- locate `claude-config`
- validate required paths
- record source metadata in `00-operator.json`

Inputs:

- `--claude-config`
- `MESH_CLAUDE_CONFIG`
- default platform paths

Outputs:

- resolved root
- selected asset paths
- missing asset diagnostics

Unit-testable functions:

- resolve root
- map logical contract names to files
- validate file existence

### W2. Contract Registry And Excerpts

Goal:

- map logical names to `claude-config` files
- extract compact prompt-safe excerpts

Initial logical names:

- `pipeline.speckit`
- `speckit.analyze`
- `speckit.implement`
- `verify.quick`
- `validate`
- `confidence-gate`

Prompt targets:

- boss: `pipeline.speckit`
- president: `speckit.analyze`
- worker: `speckit.implement`
- reviewer: `verify.quick`

MVP extraction can be simple:

- first heading
- YAML frontmatter fields when present
- first `objective`, `process`, or equivalent section when reasonably small
- truncate with explicit marker when too long

### W3. Role Policy Injection

Goal:

- prepend or append clear role policy to each role prompt
- keep role-specific forbidden actions explicit

Policies:

- boss: decision only
- president: planning only
- worker: implementation only
- reviewer: audit only

The policy text must be generated by Mesh, not trusted from `claude-config`.

### W4. Anti-Loop And Bypass Scan

Goal:

- scan role output before writing handoff JSON
- produce blocking policy violation evidence

MVP behavior:

- scan boss, president, reviewer for recursive/bypass patterns
- scan worker for nested AI, recursive Mesh, commit, and push patterns
- write `policy-violations.json` if violations occur
- fail the run on blocking violations

False-positive handling:

- not in MVP except narrow tests for quoted examples if needed

### W5. Quality Quick Sidecar

Goal:

- add `--quality off|quick`
- default `off`
- `quick` produces deterministic JSON

Inputs:

- git status
- diff stat
- test status
- allowlist
- policy scan results

Output:

```text
.mesh/runs/<run_id>/quality-quick.json
```

Exit behavior:

- failed deterministic checks fail the run unless explicitly allowed by existing
  flags or a future quality-specific allow flag

### W6. Confidence Gate Sidecar

Goal:

- add optional controller-owned call to `confidence_gate.py`

Flags:

- `--confidence-gate`
- `--confidence-step implement`
- `--allow-gate-failure`
- `--gate-timeout <seconds>`

MVP command:

```bash
python3 <claude-config>/scripts/confidence_gate.py \
  --step implement \
  --files <evidence files> \
  --json \
  --no-iterate
```

Output:

```text
.mesh/runs/<run_id>/gate-implement.json
```

Exit behavior:

- fail when JSON is missing or invalid
- fail when `final_approved=false`, unless `--allow-gate-failure`

Important:

- do not enable `--evolve` in MVP
- do not let Claude boss invoke this script directly

### W7. Controlled Iteration

Goal:

- add bounded retry only after W1-W6 are stable

Flags:

- `--max-iterations N`
- default remains `1`

Allowed retry conditions:

- no policy violation
- concrete reviewer/gate/test feedback exists
- iteration count is below max
- controller writes a new iteration sidecar

Stop reasons:

- `approved`
- `test_failed`
- `gate_failed`
- `policy_violation`
- `progress_stalled`
- `max_iterations`
- `human_review`

This workstream is post-MVP unless needed for the first serious e2e.

## CLI Shape

MVP:

```bash
./scripts/mesh speckit run <repo> \
  --feature "<feature>" \
  --team claude-codex-gemini \
  --auto \
  --with-reviewer \
  --allow-edit <path> \
  --quality quick \
  --confidence-gate
```

Debug:

```bash
./scripts/mesh speckit run <repo> \
  --feature "<feature>" \
  --print-command \
  --claude-config /Users/sam/claude-config \
  --quality quick
```

Low-cost live testing:

```bash
./scripts/mesh speckit run <repo> \
  --team local-gemini \
  --feature "<feature>" \
  --auto \
  --with-reviewer \
  --quality quick
```

## Validation Strategy

Unit tests first:

- no iTerm dependency
- no live AI dependency
- no network dependency

Test groups:

- adapter root resolution
- contract mapping
- excerpt generation
- role policy text
- forbidden output scan
- quality sidecar payload
- confidence gate command construction
- confidence gate JSON parsing
- final run status calculation

Live validation later:

- local-gemini smoke
- claude-codex-gemini smoke
- snake-game implementation with `--quality quick`
- snake-game implementation with `--confidence-gate`

## Rollout Order

1. Documentation/spec only.
2. Read-only adapter and tests.
3. Contract injection and tests.
4. Anti-loop scan and tests.
5. Quality quick and tests.
6. Confidence gate sidecar and tests.
7. Live local-gemini run.
8. Live Claude boss run.
9. Controlled iteration.

## Open Questions

- Should `confidence_gate.py` accept an environment override for config path, or
  should Mesh rely on the installed `~/.claude` copy?
- Should `--quality quick` be enabled by `--auto` after it is stable?
- Should reviewer be visible by default when `--confidence-gate` is enabled?
- How much contract text is safe to inject before it hurts CLI behavior?
- Should the boss output be required to be JSON, or only scanned text in MVP?
